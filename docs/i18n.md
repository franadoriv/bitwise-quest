# Localization (i18n)

Bitwise Quest is fully localized. The UI and every piece of content exist in:

| Locale | Name | Notes |
| --- | --- | --- |
| `en` | English | **Primary language and fallback** (`DEFAULT_LOCALE`) |
| `es` | Español | Neutral Latin American Spanish |
| `ja` | 日本語 | Natural, beginner-friendly Japanese |

There are two kinds of translatable text, handled by two mechanisms:

| Kind | Where it lives | How it is written | How it is read |
| --- | --- | --- | --- |
| **UI strings** (game chrome: buttons, HUD, results) | `lib/i18n/messages.ts` | One dictionary per locale, keyed by `MessageKey` | `t(key, vars)` |
| **Content** (lessons, regions, topics, exams, pack taglines) | `content/<lang>/` | `L(en, es, ja)` inline in the data | `tx(text)` |

## Core: `lib/i18n/text.ts`

This file has no imports so Node can load it directly from `scripts/` and `content/`.

| Export | Meaning |
| --- | --- |
| `LOCALES` | `["en", "es", "ja"] as const` |
| `Locale` | `"en" \| "es" \| "ja"` |
| `DEFAULT_LOCALE` | `"en"` |
| `LOCALE_NAMES` | Display names: `English`, `Español`, `日本語` |
| `LOCALE_SHORT` | Language button labels: `EN`, `ES`, `日本` |
| `Localized` | `Record<Locale, string>`, i.e. `{ en, es, ja }`. Prose |
| `Text` | `string \| Localized`. A plain string is **language-neutral** (code, numbers, identifiers); a `Localized` is **prose** |
| `L(en, es, ja)` | Compact constructor for content: `L("Hello", "Hola", "こんにちは")` |
| `tx(text, locale)` | Resolves a `Text`: plain strings are returned as is; `Localized` returns `text[locale]`, falling back to `text.en` if empty; `null`/`undefined` returns `""` |
| `isLocalized(v)`, `isLocale(v)` | Type guards |
| `negotiateLocale(accept)` | Picks the first supported locale from an `Accept-Language` header or `navigator.languages` (matches on the first two letters, so `es-MX` → `es`, `ja-JP` → `ja`); otherwise `en` |

## UI strings: `lib/i18n/messages.ts`

- The `en` dictionary **defines the keys**: `type MessageKey = keyof typeof en`.
- `MESSAGES: Record<Locale, Record<MessageKey, string>>` holds `{ en, es, ja }`. Because each dictionary must be a full `Record<MessageKey, string>`, **TypeScript fails `npm run typecheck` if `es` or `ja` is missing a key**.
- Keys are namespaced by screen: `common.*`, `settings.*`, `title.*`, `world.*`, `lesson.*`, `exam.*`, `review.*`, `dialog.*`...
- Placeholders use `{name}`: `"world.days": "{n} DAYS"`.

| Function | Use |
| --- | --- |
| `format(locale, key, vars?)` | Returns the string for `locale` (English if missing) with every `{var}` replaced |
| `localized(key, vars?)` | Returns a `Localized` with the message in every locale. For text the **server** builds and sends to the client, such as the exam intro dialog, exam play title and review lesson title (`lib/repo.ts`). `vars` may be a function `(locale) => vars` when a variable is itself localized |

Adding a UI string:

```ts
// lib/i18n/messages.ts
const en = { /* ... */ "world.bonus": "BONUS x{n}" };
const es: Messages = { /* ... */ "world.bonus": "BONUS x{n}" };
const ja: Messages = { /* ... */ "world.bonus": "ボーナス x{n}" };
```

```tsx
const { t } = useI18n();
<span>{t("world.bonus", { n: 3 })}</span>
```

Never hard-code player-facing strings in components. The brand name comes from `lib/brand.ts` (`BRAND.name`, `BRAND.logo`, and the localized `BRAND.tagline`), not from the dictionaries.

## React: `components/ui/I18n.tsx`

- `I18nProvider` wraps the app in `app/layout.tsx` and receives the initial locale.
- `useI18n()` returns:

| Member | Meaning |
| --- | --- |
| `locale` | Current `Locale` |
| `t(key, vars?)` | UI string via `format()` |
| `tx(text)` | Content `Text` resolved for the current locale |
| `setLocale(l)` | Writes the `locale` cookie (1 year, `path=/`, `samesite=lax`), sets `<html lang>` and re-renders. No reload |

### How the locale is chosen

1. `app/layout.tsx` (server) reads the `locale` cookie. If it holds a supported locale, that wins.
2. Otherwise it calls `negotiateLocale(Accept-Language)`, so first-time visitors get their browser language, or English.
3. The result is set as `<html lang>` and passed to `I18nProvider`.
4. The language button in `components/ui/Settings.tsx` (present in every HUD) cycles `LOCALES` in order: **EN → ES → 日本 → EN**, and calls `setLocale`.

Because content reaches the client with every locale, switching language re-renders instantly, including in the middle of a lesson.

## Fonts

| Font | Role | Japanese |
| --- | --- | --- |
| Press Start 2P | UI / headings (`--font-pixel`) | No glyphs, falls back to DotGothic16 |
| VT323 | Code (`--font-code`) | No glyphs, falls back to DotGothic16 |
| DotGothic16 | Dialog body (`--font-body`) and fallback | Covers kana and kanji |

Fonts are loaded with `next/font/google` in `app/layout.tsx`; the fallback chains are in `app/globals.css`. `html[lang="ja"] .pixel` removes letter spacing and adjusts line height for Japanese headings.

## Content rules

Every prose field typed `Text` in `lib/content/types.ts` must be `L(en, es, ja)`:

| Must be `L(...)` | Must stay a plain string |
| --- | --- |
| Dialog `text` | `code`, `line`, `starter`, `solution` |
| `act` `prompt` and step `label` | `expect`, `fallback`, `output`, `lines` |
| `error.plain` | `error.compiler` (the real rustc message) |
| Every question `prompt` and `explain` | `type` `answer` |
| `hint` | `tag` / `value` / `print` effect text |
| `say` / `banner` effect text | Slugs, ids, `concept`, `topic` |
| Lesson `title`, `enemyName` | |
| Region `name`, `subtitle` | |
| Topic `name`; exam `title`, `description`; pack `tagline` | |

`pick`/`predict` options may be plain strings (code tokens such as `"&mut x"`) or `L(...)` (prose answers such as `L("No: s1 moved to s2", ...)`). Code in exercises uses **English identifiers for every locale**, so `check.stdout` and `expect` are the same in all languages.

### What the validator enforces

`scripts/validate-content.ts` (`npm run content:check`) calls `prose()` on each of those fields:

- **Error** if the value is a plain string or a partial object, or if any locale is empty.
- **Warning** if a locale exceeds its budget. Japanese gets `ceil(budget × 0.65)` because it packs more meaning per character.

| Field | en / es | ja |
| --- | --- | --- |
| Dialog `text` | 140 | 91 |
| `explain` | 160 | 104 |
| `error.plain` | 120 | 78 |
| Exam `description` | 120 | 78 |
| `act` / `run` `prompt` | 70 | 46 |
| Question `prompt`, pack `tagline` | 60 | 39 |
| Region `subtitle` | 40 | 26 |
| Topic `name` | 36 | 24 |
| Exam `title` | 32 | 21 |
| Lesson `title` | 28 | 19 |
| Region `name` | 24 | 16 |
| `enemyName` | 20 | 13 |
| Step `label` | 16 | 11 |
| `say` / `banner` | 22 | 15 |

`hint` is typed `Text` but is not validated today; still localize it.

### Storage

SQLite stores every `Text` column as JSON (`lib/db.ts`) and `lib/repo.ts` parses it back, so the database holds all locales. Changing any translation changes the content hash and the content is reseeded on the next server start. Player saves live on the client and never store content, so they are unaffected.

## Translation guidelines

**General**

- English is the primary language: concise, plain, playful. Write it first.
- Keep the meaning and the joke, not the word order. Each locale should read as if written natively.
- Respect the budgets; short is better than complete.
- **Never translate** code identifiers, keywords, types, macros, compiler output (`error.compiler`), program output (`print`, `output`, `expect`, `check.stdout`) or error codes (`E0382`). Inline code inside prose stays as is: `L("Use &mut x", "Usa &mut x", "&mut x を使おう")`.
- Keep the emphasis style of the source: UPPER CASE for key words (`MOVE`, `OWNER`) where the English uses it.

**Spanish (`es`)**

- Neutral Latin American Spanish. Address the player as *tú*. Avoid regionalisms and *vosotros*.
- Keep established English Rust terms when that is what developers say: *ownership*, *move*, *borrow checker*, *trait*, *lifetime*, *closure*, *async*. Translate where a clear standard exists: *préstamo* (borrow), *hilo* (thread), *genéricos* (generics).

**Japanese (`ja`)**

- Natural, beginner-friendly sensei tone: friendly casual endings (〜だよ, 〜しよう, 〜してごらん), never stiff or overly formal.
- Standard terminology:

| English | Japanese |
| --- | --- |
| ownership | 所有権 |
| borrow / borrowing | 借用 |
| move | ムーブ |
| lifetime | ライフタイム |
| trait | トレイト |
| generics | ジェネリクス |
| thread | スレッド |
| closure | クロージャ |
| async | 非同期 |
| compile | コンパイル |

- Use full-width punctuation (、。！？：) in Japanese prose and leave a space around inline Latin code where it helps readability (`b にわたす`).
- Japanese has no capitalization; use 「」 or katakana for emphasis.

## Adding a locale

Example: adding French (`fr`). Every step is enforced by a tool, so you cannot forget one silently.

1. **Core.** In `lib/i18n/text.ts`, add `"fr"` to `LOCALES`, `fr: "Français"` to `LOCALE_NAMES` and `fr: "FR"` to `LOCALE_SHORT`. `Localized` now requires `fr` (TypeScript flags every literal missing it), `isLocalized` and `localized()` follow `LOCALES` automatically, and `L()` must take a fourth argument: change it to `L(en, es, ja, fr)`.
2. **UI dictionary.** In `lib/i18n/messages.ts`, add `const fr: Messages = { ... }` and register it in `MESSAGES`. TypeScript reports every missing key. Also add `fr` to `localized()`, which lists locales explicitly.
3. **Brand.** Add `fr` to `BRAND.tagline` in `lib/brand.ts`.
4. **Content.** Extend every `L(...)` call in `content/` (and in `content/index.ts` for "soon" cartridges). Run `npm run content:check`: the validator lists every field still missing `fr`, and `npm run typecheck` flags every `L()` call with the wrong number of arguments.
5. **Fonts.** Check the pixel fonts cover the script. Latin scripts are covered by the `latin` / `latin-ext` subsets in `app/layout.tsx`; for other scripts, add a fallback font to the chains in `app/globals.css` and, if needed, a `html[lang="xx"]` rule for spacing.
6. **Switcher.** Nothing to do: the button in `components/ui/Settings.tsx` cycles `LOCALES` in order and shows `LOCALE_SHORT`.
7. **Budgets.** If the new script is denser or wider, add a factor next to the Japanese one in `prose()` in `scripts/validate-content.ts`.
8. **Playtest.** `scripts/playtest.mjs` accepts `--locale=fr` once the dictionary exists.

### Checklist for a new locale

- [ ] `LOCALES`, `LOCALE_NAMES`, `LOCALE_SHORT` and `L()` updated in `lib/i18n/text.ts`.
- [ ] Dictionary added to `MESSAGES` and to `localized()` in `lib/i18n/messages.ts`.
- [ ] `BRAND.tagline` translated.
- [ ] `npm run typecheck` passes.
- [ ] `npm run content:check` reports 0 errors (every `L(...)` extended).
- [ ] Font coverage checked (and a `--locale=<new>` playtest run).
- [ ] `npm run playtest -- /play/rust/lesson/hello-let --locale=<new>` finishes and the screenshots show no overflow or missing glyphs.

## Checklist for translating content

- [ ] English written first; Spanish and Japanese follow the guidelines above.
- [ ] Code, compiler output, program output and error codes untouched.
- [ ] `npm run content:check` with 0 errors and no budget warnings in your files.
- [ ] Playtest with `--locale=es` and `--locale=ja`.
